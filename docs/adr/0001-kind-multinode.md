# ADR-0001: 로컬 멀티노드 클러스터로 kind 채택

- 상태: Proposed
- 날짜: 2026-11-14

## 맥락
단일 호스트에서 멀티노드·존 분산·노드 장애를 재현해야 하고, Claude Code가 스크립트로 생성/삭제를 반복할 수 있어야 한다.

## 결정
kind(Docker 컨테이너 노드)로 컨트롤 플레인 1 + 워커 4를 구성한다. 노드 이미지는 digest로 고정하고, 사용자 정의 Docker 네트워크(`kind-boutique`, 고정 서브넷)를 사용한다.

## 대안
- k3d: 가볍지만 k3s 배포판 특성(내장 구성요소 비활성화 필요)으로 업스트림 kubeadm 클러스터와 차이가 생김
- minikube 멀티노드: 드라이버별 동작 차이, CNI 교체 시나리오가 덜 일반적
- VM + kubeadm(Vagrant/Multipass): 가장 현실적이지만 자원·시간 비용이 크고 재구축이 느림

## 결과
- (+) 수 분 내 재구축, `docker stop`으로 노드 장애 재현, 업스트림 kubeadm 기반
- (−) 노드가 커널을 공유(커널 기능은 호스트에 의존), macOS에서는 VIP가 호스트로 라우팅되지 않음 → probe 컨테이너로 검증
